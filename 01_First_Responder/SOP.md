\# Standard Operating Procedure (SOP)

\## Case Omega – First Responder Procedure



\*\*Case ID:\*\* OMEGA-001  

\*\*Incident Type:\*\* Simulated Ransomware Incident  

\*\*Environment:\*\* Fictional Healthcare Network  

\*\*Investigation Type:\*\* Academic Digital Forensics Simulation



\### 1. Purpose



The purpose of this SOP is to establish a consistent procedure for documenting and preserving digital evidence during the fictional Case Omega ransomware investigation.



\### 2. Scope



This procedure applies only to the simulated environment and synthetic evidence created for this academic project. No real healthcare network, patient information, or production system will be accessed.



\### 3. First Responder Responsibilities



The first responder must:



\- Record the date and time when the simulated incident is reported.

\- Record the incident location and system identification details.

\- Document the visible condition of the simulated workstation or server.

\- Maintain an investigation activity log.

\- Identify potential digital evidence.

\- Preserve evidence records and maintain chain of custody.

\- Avoid changing or deleting original evidence files.



\### 4. Initial Incident Documentation



Record the following information:



| Field | Details |

|---|---|

| Case ID | OMEGA-001 |

| Incident Type | Simulated ransomware incident |

| System | Fictional healthcare server |

| Date and Time | To be recorded during simulation |

| First Responder | Student investigator |

| Environment | Isolated academic lab |



\### 5. Scene Documentation



The investigator will document the simulated scene using:



\- Photographs or screenshots of the fictional incident environment.

\- A simple scene layout sketch.

\- System identification details.

\- Evidence identification tags.

\- Notes describing visible warning messages or simulated ransom notes.



All screenshots and sketches must be stored in the `06\_Screenshots/First\_Responder/` folder.



\### 6. Identification of Potential Digital Evidence



The following synthetic evidence may be identified:



1\. Simulated system logs.

2\. Synthetic login records.

3\. Sample ransom note created for the assignment.

4\. Harmless test files representing affected files.

5\. System configuration information.

6\. Synthetic browser history records, if included in the scenario.



\### 7. Evidence Preservation



\- Use only synthetic files created for this project.

\- Keep original sample files unchanged.

\- Create separate working copies for analysis.

\- Record file names, sizes, and SHA-256 hashes.

\- Document every evidence transfer or handling activity.



\### 8. Safety Precautions



\- Do not connect the simulation to a real healthcare network.

\- Do not execute real ransomware or unknown malware.

\- Do not access real patient records.

\- Use harmless test data and simulated indicators only.



\### 9. Initial Findings



The first responder will record observations without making unsupported conclusions. Detailed technical findings will be documented in the malware analysis and final forensic report sections.
